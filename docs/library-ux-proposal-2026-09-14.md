# 书架 UX 改版建议

日期：2026-09-14。状态：用户确认方案 B，已实施并完成 Android 原生布局验证。

用户反馈：发现页基本可接受，主要问题是书架的继续阅读与离线下载都很长；
续读最近几本与从大量下载中选书两种行为都很常见。

## 推荐结构

在现有“书架”一级目的地内设置 **续读 / 离线 / 收藏** 三个平级入口。
书签和账号阅读历史保留独立入口，不随列表长度下移。
首次进入默认续读；同次运行内保留上次选择、各列表搜索条件、排序与滚动位置，
包括一级导航切换及横竖屏变化。没有新增跨进程的书架视图偏好存储。

### 续读

- 继续使用本机进度，默认最近阅读在前；主操作直达已存语义位置。
- 最近一项适度突出，其余为紧凑文字行，保留书名、阅读位置及必要的进度信息。
- 详情作为行尾的次级操作，避免每本都独占一整行“小说详情”。
- 提供书名搜索；本机续读不依赖登录。
- 不自动把“有阅读进度”解释为主动管理的“在读”。置顶、归档、读完标记另行定义。

### 离线

- 完整列表直接可达，提供书名搜索、当前最近活动排序及书名排序。
- 区分已完成、未完成、失败或暂停；不能把部分下载显示成整本已下载。
- 找书与处理下载任务分别有明确操作：阅读入口与下载管理入口。
- 主操作可按是否有进度显示续读或开始阅读；实施时需验证当前章节和译源的本地
  可用性，不能直接复用“进入小说详情”回调后宣称已经优化续读路径。
- 当前下载按“小说 × 译文来源”分组。同书多译源必须保留可识别入口；若在显示层
  合成一行，展开后仍能选择、管理每个译源，不能合并删除语义。
- 管理复用已有暂停、继续、重试和删除确认。删除下载继续保留阅读进度及书签。

### 收藏、书签和历史

- 收藏保持账号收藏夹结构，分别表达未登录、不可用、空和有内容。
- 书签是本机具体位置，不混入收藏；完整书签列表可后续按作品分组。
- “账号阅读历史”来自远端，不是本地续读的“查看全部”。

## 三种方案的取舍

| 方案 | 收益 | 代价与适用范围 |
| --- | --- | --- |
| A：限量分区概览 | 页面长度可控；展示最近 3 本，其余通过查看全部进入 | 查旧书多一层；每类内容都要明确容量边界。更适合主要续读少数作品的习惯。 |
| B：续读 / 离线 / 收藏切换 | 列表彼此不挤占入口，适合两种任务都频繁的用户 | 需要保留各类别的浏览状态，并明确书签和历史位置。**本轮推荐。** |
| C：合并本机书籍 + 状态筛选 | 每本一个入口，按书名找书统一 | 需处理多译源、部分离线、进度与动作分流；远端收藏仍独立。可作为后续方案。 |

仅将长列表折叠或改成横向轮播，会转移寻找成本；搜索、分类入口和状态保留仍然需要。
封面网格可作为将来的显示选项，当前问题无需先依赖封面资源或更换主题解决。

## 实施边界

首轮已完成分类切换、紧凑条目、现有字段搜索筛选、视图状态保留和下载管理接入。
展示“昨天”等具体活动时间需要给视图模型补字段；持久化置顶、归档和读完状态需要
明确新模型，不能借删除阅读进度或下载实现。

目前书架覆盖网络小说。文库 EPUB 的存储与内存阅读位置尚未接入此书架，若希望
同时管理文库，需要独立的存储索引与进度接线，不属于纯布局修改。

实施后的验证至少覆盖：0/5/100 条虚构数据；切换类别后搜索和位置保留；长中日文与
放大字体；同书多译源；部分下载、失败、暂停；未登录收藏；删除下载保留进度与书签。
入口随长列表是否仍可达需在移动视口验证；平台手势和性能以对应原生设备结果为准。

## 已实施的行为与验证

- 续读与离线各有书名搜索（中日文）、最近活动／书名排序，离线另有状态筛选。
  搜索、排序或状态改变时回到该列表顶部；分类之间不会相互覆盖条件。
- 收藏保留远端收藏夹，区分登录提示、服务不可用、空和有内容。书签进入独立列表；
  顶部历史图标明确标注“账号阅读历史”。
- 离线阅读在启动时重新核对该小说与译源的下载副本及正文。优先恢复可用的保存位置，
  否则选目录顺序中的首个本地可读章节。不会因加载窗口包含前章而误从前章开始，
  也不会仅因点了某个译源就改变全局默认译源。无正文的过期记录由阅读加载错误页处理。
- 修复了底部导航与侧边导航切换时重建书架的问题；未新增数据库表或改变删除语义。
- 完整 Flutter 回归 344 项通过；随后增加的屏幕阅读器操作测试与相关定向检查另行通过。
  覆盖同书多译源、位置可用／不可用、清缓存后离线阅读、导航适配、100 条惰性构建、
  独立搜索／排序／滚动、空与远端状态，以及 320/720/1000 宽度下的 200% 字体。
- 应用源码及测试静态检查通过：`flutter --no-version-check analyze lib test integration_test test_driver`。
  明确限定源码目录，避免将工作区已有的 `build/` 内其他 Flutter SDK 调试副本作为本项目分析。

原生证据日期 2026-09-14，代码基于 `a74670d` 加本次未提交改动。设备为
`novelia_api36` Android 16 / API 36 ARM64 模拟器，1080×2400 竖屏与 2400×1080 横屏。
截图来自实际 Flutter `NoveliaShell` 与书架组件，使用虚构的 0/5/100 本书、双译源和
不同下载状态；覆盖浅色、深色、100%/200% 文字、长列表、书签和收藏。
入口不打开持久数据库或真实网络服务；这些布局截图不替代真实下载服务的端到端测试。

## 分类滑动补充（2026-09-14）

根据用户反馈，续读／离线／收藏增加左右滑动，顶部标签与内容共用分页状态。
滑动时收起搜索键盘，各页继续保留搜索、排序、筛选及滚动位置；离线筛选条的横向
滚动保持独立。点击标签的过渡遵循系统关闭动画设置。

基于 `36619e6` 的本次工作区改动通过 63 项书架及导航回归和修改文件静态检查。
同一 Android 16 模拟器的原生 fixture 流程通过：0/5/100 本书下双向滑动、点击后
继续滑动、长列表位置恢复，并重新采集浅／深色与大字横屏截图。
该补充未在 HarmonyOS 或 iOS 设备上验证系统边缘手势。
