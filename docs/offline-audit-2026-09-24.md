# 离线功能复查 · 2026-09-24

本次检查以“本机已有内容，在无网、请求一直不返回、登录状态不可用、关闭重开后仍能使用”为边界。使用虚构数据和临时数据库、EPUB 文件，没有访问或修改用户设备上的阅读数据。

## 确认的问题与修复

| 问题 | 原来的失效路径 | 当前处理 |
| --- | --- | --- |
| 下载副本被临时缓存替代 | 读取章节只取最新 payload，没有选择当前译源的受保护下载；后台还会重新取正文 | 按小说、章节和译源解析实际下载引用；阅读下载时不做联网复核 |
| 离线切换译源仍使用旧来源 | 阅读会话的译源固定在打开时，设置菜单切换没有重选已有副本 | 切换时重新选择对应下载，更新已载入章节；丢弃旧来源的迟到刷新 |
| 网站删章后本地入口丢失 | 新目录覆盖旧目录，阅读启动要求章节仍存在于目录 | 从仍被本地副本引用的正文头部补出“本地保存章节”；续读、书签和下载保留入口 |
| 本地书籍详情等网络 | 已有本地目录仍先请求网站，无网或请求不结束时不能及时打开 | 从本机书架进入已有书籍，直接读取本地目录 |
| 文库续读不持久保存 | 页内比例和 EPUB 章节序号只有内存变量 | 按已下载 EPUB 保存位置文件，离线列表和详情入口共用；坏进度文件不阻止打开正文 |
| 文库隐藏窗口无法完成布局 | 初始化和重排只等待动画帧，隐藏原生窗口可能暂停这些回调 | 字体与图片就绪后，布局等待有定时回退；保留原有真实分页检查 |
| 关闭文库时进度被覆盖 | 原生视图退出时产生的滚动/尺寸变化仍被当成阅读进度 | 已退出的页面停止接收和保存位置事件 |

同时避免书架计算进度时解码所有插图字节，避免图片下载接入后扩大启动时的内存和解析开销。

此前已修的账号过滤与正文插图下载继续纳入回归：本地书架、阅读位置、书签和下载不按网站账号隐藏；已下载图片随正文持久保存，旧下载可补图。

## 尚未覆盖的离线功能

- 文库 EPUB 不在统一网文下载管理、容量统计和 `.jfzbackup` 导出范围内；文库只能从“文库 → 已下载”读取，其位置文件也不随现有备份导出。
- 云端收藏夹和云端阅读历史没有持久化的本地列表，断网时这些云端页面不可浏览。本机续读与书签是另外保存的本地数据。
- 文库阅读器支持 EPUB 包内图片；远程外链图片不会被当前 EPUB 保存逻辑收集。尚无本次用户小说 EPUB 的证据，不能据此认定用户下载的文库一定受影响。

这些是现有功能边界或缺口，不能当成“离线已经全部可用”。
